问题与审计
上一版等权修正降低人行道误放行，但也降低道路召回率。
seed 17 的原验证子集中，新增漏检 44490 格，其中 87.2% 无地面回波，87.4% 位于
12 米以外；无地面回波的基线正确道路被删除率为 2.73%，有回波为 1.33%。
保留场景新增漏检 6717 格，其中 88.9% 无地面回波，87.7% 位于 12 米以外。
道路内部同样存在大量漏检，不应仅以边界误差解释。图像仅提供场景背景，没有据此
认定地图标签错误。全部三个种子的分组统计见 audit.json。

改动
保持等权相机/LiDAR修正网络、冻结 BEVFusion 和 200 场景基线，道路阈值仍为 0.60。
仅修改训练损失，并收紧开发集选模条件。
对于训练集中真值为道路、且基线概率 >= 0.60 的栅格，惩罚修正后 logit 低于基线：
L = BCE + lambda * sum(w * protected * relu(baseline_logit - new_logit)^2) / sum(w * protected)
无地面回波时 w=2，有地面回波时 w=1。保护掩码仅用于训练损失，不参与推理。

对照与选择
相同 2400 帧 / 200 场景，种子 17/29/43，12 个 epoch，batch 24，lr 0.0003。
lambda 候选为 0.25、1、4；另设 lambda=0 的无保留损失对照。
所有组开发集选模都要求：IoU >= 基线、人行道误放行 <= 基线、召回率下降 <= 0.2pp。
在满足者中选 IoU 最高的检查点；若无可行检查点，则明确回退到未修改基线。
按三个种子的开发集结果统一选择 lambda=0.25，先写入 locked.json，再评估两套集合。
没有根据评估结果重新选权重、阈值或种子。
lambda=0 的 17/29 种子回退到基线，43 种子选到可行模型。
其逐 epoch 开发集 IoU 与上一版等权训练完全复现，说明训练对照一致。

解释与限制
相对固定基线，新版原验证子集 IoU +0.5967pp，召回 +0.1165pp，人行道误放行 -11.41%；
保留场景 IoU +0.4877pp，召回 +0.2361pp，人行道误放行 -14.93%。
三个种子的两套评估均观察到 IoU 提升和误放行减少。
无地面证据区域道路召回率也在平均层面提高：原验证集 87.0743% -> 87.2547%，
保留场景 85.5526% -> 85.8341%。
相对上一版等权修正，误放行增加约 12.8% / 16.7%，换回约 1.33pp / 1.04pp 召回率。
这不是所有指标都优于上一版，保留集 IoU 还比上一版低约 0.059pp。

seed 29 在原验证子集召回仍下降 0.2617pp，超过开发集预设的 0.2pp 目标。
因此只能说平均结果保住了召回，不能声称每个种子都达到评估约束。
seed 43 在保留场景人行道误放行差值的场景 bootstrap 95% 区间跨零。
集合已被用于此前诊断，不构成新的盲测；没有测量端到端时延。
本轮保持固定 baseline_v1 不变，将新版作为候选保存。

文件与复现
road_preserve_audit.py：错误归因及典型样本。
road_preserve_train.py setup / train --seed N / lock / evaluate --seed N。
road_preserve_summary.py：三种子汇总和案例对比。
服务器 p0_25_17.pt、p0_25_29.pt、p0_25_43.pt 为被选中的保留约束模型。
selection_*.json 保存完整训练/开发集曲线；results_*.json 保存评估及场景 bootstrap。
summary.json、protocol.json、locked.json 保存结果与固定口径。
本次直接用 logit 阈值比较，原验证集基线与上一版 sigmoid 阈值比较有 1 格数值舍入差异；
影响约 0.00003pp IoU，人行道误放行和召回不受影响。两组配对比较使用同一重算基线。
